sandbox 정책 확장과 보강
무엇 sandbox.userPolicy.network.extraCaCertificates로 TLS를 가로채는 프록시 환경에서 sandbox 명령이 커스텀 CA 인증서를 신뢰하게 할 수 있다. macOS에서는 sandbox.userPolicy.seatbelt.extraMachLookups로 특정 Mach 서비스 조회를 허용한다(Keychain 접근 없이). Windows sandbox 패키지 조회는 기본 활성화됐다. Swift·Bun 도구의 캐시 접근도 허용됐고, 연결된 worktree에서 Git commit·브랜치 생성·stash가 다시 동작한다. /sandbox policy는 깨진 symlink 허용 항목을 경고하고 sandboxed gh 명령이 쓰는 GitHub 계정도 보여준다.
어떻게 쓰나 user 또는 managed settings에 위 설정을 넣는다. Windows 패키지 조회를 끄려면 sandbox.userPolicy.capabilities를 []로 설정한다. 정책 확인은 /sandbox policy로 한다. env 설정으로 Copilot이 시작하는 모든 프로세스(shell 명령, LSP·MCP 서버, hook, extension)에 환경 변수를 줄 수도 있다.
의미 사내 프록시나 sandbox 환경에서 CLI를 쓰는 개발자와 관리자에게 의미가 있다.

Assisted Permissions·권한 승인 동작 개선
무엇 Assisted Permissions가 이전 시도가 실패했다는 이유만으로 shell 명령 재시도를 중복으로 거부하지 않는다. Autopilot에서는 자동 거부된 작업을 이후 채팅에서 요청하면 한 번 재시도할 수 있고, 이 재시도도 권한 검토를 거친다. plan mode에서는 Git 브랜치 생성이나 패키지 설치 같은 작업을 plan 승인 전에 자동 승인하지 않고 먼저 묻는다. MCP 서버 도구를 승인해도 서버 이름이 내장 권한 유형과 같다는 이유로 shell 명령이나 memory 저장까지 승인되지는 않는다. Autopilot으로 시작하면 extension을 실행하기 전에 각각 묻는다.
어떻게 쓰나 별도 설정 없이 1.0.115~1.0.117에서 자동 적용된다. 세션을 재개할 때 유지되는 승인은 권한 프롬프트와 help에 설명이 보강됐다.
의미 Autopilot과 권한 자동 검토를 쓰는 사용자에게 의미가 있고, MCP 승인 범위가 좁아져 보안상 더 안전하다.

해설 보기 · modelcontextprotocol/servers v2.6.0은 git·memory·fetch 서버의 취약점 8건을 고치고, 앞선 v2.5.0의 미완 수정 2건을 마무리한 보안 릴리스다. 이 밖에 filesystem의 Windows 보강과 everything 서버의 기능 추가가 있고, 그 밖에 테스트·CI·문서 등 내부 정리 다수가 포함됐다.
mcp-server-git 2026.11.27 보안 수정
무엇 mcp-server-git의 취약점 6건을 고쳤다. Git LFS가 저장소 설정(.git/config)에 적힌 프로그램을 실행하던 문제, --repository 루트가 다른 저장소로 바뀔 수 있던 문제, git_remote가 자격 증명을 노출하던 문제, repo_path의 환경변수 확장, alternates 파일 조작으로 다른 저장소 객체를 읽던 문제, git_merge가 .env 같은 무시된 파일을 덮어쓰던 문제다. 병합·체크아웃으로 작업 트리가 옮겨지는 경우를 막는 --repository 재검사도 완성했다.
어떻게 쓰나 mcp-server-git을 2026.11.27로 올린다(영향 범위: 2026.11.18까지). LFS 다운로드는 GIT_LFS_SKIP_SMUDGE=1로 꺼지고, 이 키들은 저장소 범위에서 비워진다. 별도 설정은 필요 없다.
의미 git 서버를 에이전트에 연결해 쓰는 모든 사용자에게 중요하다. 읽기 전용 도구인 git_status 등으로도 서버 권한의 프로그램 실행이 가능했으므로 업그레이드를 권한다.

server-memory 2.2.2: 임시 파일 경쟁 조건 수정
무엇 saveGraph가 임시 파일의 권한을 바꾸고 경로로 rename하던 탓에, 그래프 디렉터리에 쓸 수 있는 계정이 임시 이름을 심볼릭 링크로 바꿔 메모리 경로 밖 파일의 권한을 바꿀 수 있었다(GHSA-48j5-hj63-c82c). 이제 임시 파일을 배타적으로 만들고 자기 핸들로 쓰며, 이름이 바뀌었으면 저장을 거부한다.
어떻게 쓰나 @modelcontextprotocol/server-memory를 2.2.2로 올린다. 날짜 버전(2025.x, 2026.x)을 쓰는 경우 패키지 관리자가 2.2.2를 업그레이드로 인식하지 않으므로 npm install @modelcontextprotocol/server-memory@2.2.2처럼 명시해 설치해야 한다.
의미 memory 서버를 쓰면서 그래프 디렉터리를 다른 계정과 공유하는 환경에서 의미가 있다. 날짜 버전 사용자는 직접 설치해야 한다.

server-filesystem 2.4.1: Windows 디렉터리 검사 강화
무엇 Windows에서 list_directory, list_directory_with_sizes, directory_tree, search_files가 읽기 전후로 디렉터리를 검사한다. 경로에 junction이나 symlink가 있거나 읽은 뒤 다른 디렉터리를 가리키면 "Access denied - a directory on the path changed during the operation"으로 거부한다. 읽는 도중 바꿨다 되돌리는 교체는 Windows에서 아직 감지하지 못한다. macOS와 Linux는 변경이 없다.

의미 Windows에서 filesystem 서버를 쓰는 사용자에게만 해당한다. macOS·Linux 사용자는 몰라도 된다.
