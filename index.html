Enterprise Admin Console 조직 로그인
무엇 Anthropic의 Enterprise Admin Console이 관리하는 조직에 로그인할 수 있다. claude auth login 후 Claude Code가 조직 설정을 적용하고 조직의 클라우드 제공자나 게이트웨이를 사용한다. 로그인 링크도 훨씬 짧아졌고, 전체 링크가 필요하면 CLAUDE_CODE_FULL_SIGN_IN_LINK=1을 쓴다.
어떻게 쓰나 claude auth login을 실행한다. 짧은 링크에 오류가 나거나 스크립트가 링크 값을 읽어야 하면 CLAUDE_CODE_FULL_SIGN_IN_LINK=1을 설정한다. /login, claude setup-token의 링크도 짧아졌다.
의미 Enterprise Admin Console로 조직을 관리하는 팀에 해당한다. 개인 사용자는 몰라도 된다.

auto mode 확대와 Code Mode 개선
무엇 Amazon Bedrock, Google Cloud의 Agent Platform, Microsoft Foundry, Claude apps gateway에서 Claude Opus 4.6과 Sonnet 4.6용 auto mode가 추가됐다. 권한 모드를 정하지 않은 대화형 세션은 auto mode로 시작한다. Code Mode는 agent teams와 OpenTelemetry를 켠 채로도 쓸 수 있고, 스크립트 관련 오류가 많이 고쳐졌다.
어떻게 쓰나 해당 제공자에서 대화형 세션을 열면 권한 모드를 따로 정하지 않았을 때 auto mode로 시작한다. Code Mode는 agent teams나 OpenTelemetry events·metrics를 켠 상태에서도 켤 수 있다. 이미 켜 둔 경우 teams가 켜진 세션은 Code Mode로 시작한다.
의미 서드파티 제공자나 게이트웨이로 Claude Code를 쓰는 팀, Code Mode 사용자에게 의미가 있다.

Self-hosted runner 옵션·지표 추가
무엇 self-hosted runner에 시작 폴더를 지정하는 --start-dir, 저장소 폴더를 지정하는 --repository-folder, spawn-runner hook에 세션 라벨을 넘기는 --hook-label과 --metadata가 추가됐다. /metrics에는 대기 시간과 시작 포기 횟수 지표가 늘었다. 플러그인 마켓플레이스나 git 거부 시 안내도 생겼다.
어떻게 쓰나 --start-dir 또는 SELF_HOSTED_RUNNER_START_DIR, --repository-folder(--capacity 1에서), claude self-hosted-runner orchestrator의 --hook-label, claude --environment의 --metadata key=value를 쓴다.
의미 self-hosted runner를 운영하는 관리자에게만 해당한다. 403 로그 문구가 바뀌어 로그 알림 규칙 수정이 필요할 수 있다.

해설 보기 · modelcontextprotocol/servers v2.5.0은 mcp-server-git, server-filesystem, server-everything의 보안 취약점 8건을 고친 보안 릴리스다. 모든 참조 서버가 Streamable HTTP도 지원하게 됐고, memory 서버에는 쓰기 제한 옵션이 들어갔다. 그 밖에 문서·CI·의존성 정리 등 내부 변경이 있다.
mcp-server-git 2026.11.18 보안 수정 6건
무엇 저장소 설정이 서버 권한으로 외부 프로그램을 실행하게 만들 수 있던 문제들을 막았다. git_merge 뒤 자동 maintenance 실행을 끄고(maintenance.auto=false, gc.auto=0), 누락된 객체의 lazy fetch를 끄고(GIT_NO_LAZY_FETCH=1), 파일을 쓴 뒤 filter·merge driver를 다시 읽는다. 빈 이름 driver도 비우고, 작업 트리 밖을 가리키는 index 항목을 거부하며, submodule 설정이 프로그램을 실행하지 못하게 했다.
어떻게 쓰나 mcp-server-git를 2026.11.18로 올린다. 설정할 것은 없다. 낡은 Git에서는 promisor remote가 선언된 저장소나, submodule을 체크아웃한 저장소(Git 2.33 미만)를 거부한다. --repository 제한 검사는 쓰기 뒤에 아직 반복되지 않는다(#5599).
의미 신뢰할 수 없는 저장소를 mcp-server-git로 다루는 사용자는 바로 업그레이드해야 한다. 영향 범위는 2026.11.11까지의 버전이다.

server-filesystem 2.4.0: 디렉터리 목록 검사 우회 수정
무엇 list_directory, list_directory_with_sizes, directory_tree, search_files가 디렉터리를 검사한 뒤 같은 디렉터리를 그대로 나열한다. 검사와 나열 사이에 디렉터리를 symlink로 바꿔치기해도 허용 디렉터리 밖의 항목 이름이 반환되지 않는다. 이 보호는 Linux와 macOS에만 적용되고, Windows는 아직 고정되지 않았다(#5600).
어떻게 쓰나 날짜 버전(2025.x, 2026.x) 사용자는 패키지 관리자가 2.4.0을 업그레이드로 제안하지 않는다. 직접 설치해야 한다: npm install @modelcontextprotocol/server-filesystem@2.4.0
의미 filesystem 서버를 쓰는 사용자에게 의미가 있다. 날짜 버전을 쓰고 있다면 명시적으로 설치해야 한다. Windows에서는 이 수정이 적용되지 않는다.

memory 서버 쓰기 제한 옵션과 lock 처리 개선
무엇 server-memory 2.2.1에 그래프 크기에 대한 opt-in 쓰기 제한이 추가됐다(#5534). 종료나 SIGINT/SIGTERM 때 잡고 있던 lock 파일을 풀고, stale lock을 깰 때 다른 프로세스의 살아 있는 lock을 지우지 않게 했다. Streamable HTTP 서버가 멈출 때도 lock을 푼다.
어떻게 쓰나 원문에 사용법 없음. 쓰기 제한은 선택 사항(opt-in)이라는 설명만 있고, 설정 이름은 적혀 있지 않다.
의미 memory 서버를 장기간 돌리거나 여러 프로세스에서 쓰는 사용자에게 도움이 된다.
