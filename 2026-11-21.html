무엇 전에는 모델의 기억에서 대상 버전 번호를 가져왔다. 이제 명령이 버전을 조회하고 지원 종료일, 출처, 확인일, 상태를 담은 Target versions 표를 만든다. 사용자가 지정한 버전은 유지하되, 지원이 끝났으면 경고와 지원되는 대안을 보여 준다. 조회가 모두 실패하면 해당 행을 unverified로 표시하고, 빌드 전에 사람이 버전을 확정한다. 공통 규칙은 references/target-versions.md에 있다.
어떻게 쓰나 proposes·confirms·builds 단계의 명령(reimagine, uplift, brief, preflight 등)이 자동으로 적용한다. 별도 설정은 필요 없다. 플러그인 버전은 1.1.0이다.
의미 레거시 코드를 현대화하는 개발자에게 의미가 있다. 이미 지원이 끝난 버전을 목표로 잡는 일을 줄여 준다.

무엇 (1) 세션 저장소가 아닌 다른 저장소는 git 실행 방식을 바꾸는 설정이 있으면 건너뛴다. 이 경우 커밋·푸시·턴 종료 리뷰가 아무 알림 없이 실행되지 않는다. (2) 커밋·푸시 리뷰가 큰 diff를 통째로 메모리에 올리지 않고 스트리밍으로 읽는다. 5,800개 파일 import에서 최대 메모리가 6,350MB에서 53MB로 줄었다. 의미 security-guidance를 쓰는 사용자 중 대형 커밋을 다루거나, macOS python.org Python이나 Windows pyenv-win을 쓰는 사람에게 의미가 있다.

해설 보기 · Gemini CLI v0.69.0과 v0.70.0 릴리스 묶음이다. /stats heatmap, 커스텀 테마용 theme.json, /model 인자 검증, API 타임아웃 설정이 추가됐고, 보안·정책 평가 수정이 이어졌다. 그 밖에 다수 건은 내부 정리와 버그 수정이다.
/stats heatmap 하위 명령
무엇 /stats 명령에 heatmap 하위 명령이 생겼다. 일별 토큰 사용량을 히트맵(날짜별 농도 표시)으로 보여 준다.
어떻게 쓰나 Gemini CLI에서 /stats heatmap을 실행한다. 그 밖의 옵션은 원문에 사용법 없음.
의미 토큰 사용 추이를 날짜별로 확인하려는 사용자에게 의미가 있다.
출처1
standalone theme.json 커스텀 테마
무엇 커스텀 테마를 별도 theme.json 파일로 설정할 수 있게 됐다. 테마 파일의 홈 디렉터리 확인에는 isSubpath를 쓰도록 고쳤다.
어떻게 쓰나 원문에 사용법 없음. 파일 위치와 형식은 원문에 없다.
의미 테마를 직접 꾸며 쓰는 사용자에게 의미가 있다. 나머지는 몰라도 된다.
출처1
/model 인자 검증과 API 타임아웃 설정
무엇 /model 명령이 모델 이름을 검증하고 직접 인자를 받는다. 60초인 API 헤더 타임아웃은 모든 인증 방식에서 덮어쓸 수 있다. 요청 타임아웃이 기본 300초를 넘으면 undici bodyTimeout(응답 본문 대기 시간)도 함께 늘린다. models list는 출력 토큰 한도를 정확히 표시한다.
어떻게 쓰나 /model 뒤에 모델 이름을 바로 붙인다. 타임아웃은 설정 model.requestTimeoutMs 또는 환경 변수 GEMINI_API_HEADERS_TIMEOUT_MS로 바꾼다.
의미 응답이 느린 모델이나 네트워크 환경에서 타임아웃으로 끊기던 사용자에게 도움이 된다.
출처1 · 출처2
셸 명령·MCP 보안과 정책 평가 수정
무엇 권한이 안전하지 않은 command를 가진 시스템 MCP 서버는 건너뛴다. 확장이 풀리지 않은 셸 명령은 ASK_USER(사용자 확인)를 유지한다. commandPrefix와 commandRegex 규칙은 최상위 command 인자에 맞춰 비교한다. 정책 argsPattern 평가는 re2js를 써 선형 시간으로 처리한다. 링크 경로를 공개하고 동의 프롬프트 기본값을 no로 바꿨다. IDE 연동은 사용자별 discovery 디렉터리와 원자적 포트 파일 쓰기를 쓴다.
어떻게 쓰나 별도 설정 없이 업데이트하면 적용된다.
의미 정책 규칙과 MCP 서버를 쓰는 환경, 보안에 민감한 사용자에게 의미가 있다.
출처1
세션·입력·멈춤 관련 버그 수정
무엇 유니코드 프롬프트는 보존하고 세션 미리보기의 ANSI 조각은 제거한다. 인증 재시작 때 선택한 워크트리를 유지한다. 네트워크 장애 때 로딩이 몇 분씩 멈추는 문제와 여러 시간 이어지는 쿼터 재시도를 막는다. @file 참조의 앞뒤 공백을 보존한다. 파이프 stdin은 EOF까지 기다린다. 헤드리스 중단 때는 자식 프로세스를 종료한다. macOS에서는 PTY 파일 디스크립터 누수를 막고 Seatbelt 샌드박스 진입 전에 폴더 신뢰를 확인한다.
어떻게 쓰나 원문에 사용법 없음. 업데이트하면 적용된다.
의미 일상 사용 중 겪던 멈춤이나 입력 깨짐이 줄어든다.

무엇 코딩·업무·과학 작업을 빠르게 끝내는 Gemini 4 모델이다. 컨텍스트 창은 100만 토큰이다. 가격은 입력 100만 토큰당 $3(캐시 입력 $0.15), 출력 100만 토큰당 $15다. 사고 수준(thinking level)은 4단계이며 기본값은 high, 가장 깊은 단계는 xhigh다. 원문은 Carbon보다 작업당 비용이 32% 낮다고 밝혔다.
어떻게 쓰나 Google AI Studio의 Gemini API, Gemini for business(API와 모델 드롭다운)에서 쓴다. 유료 Google AI Pro·Ultra 구독자는 Google Antigravity와 Gemini 앱에서도 쓴다. 오늘부터 순차 제공 중이다.
의미 에이전트형 코딩과 장시간 작업에서 비용과 성능을 맞추려는 개발자에게 의미가 있다. 사고 수준으로 토큰 비용을 조절할 수 있다.
출처1
Google Antigravity에서의 에이전트 코딩
무엇 Neon은 장시간 도구 호출 작업을 위해 설계됐다. 불필요한 파일 읽기를 줄이고, 진행 상황을 공유하며, 긴 세션의 컨텍스트 압축(compaction)을 안정적으로 처리한다. 여러 파일에 걸친 디버깅과 리팩터링에서는 필요한 부분만 고치는 편집을 한다. Antigravity에서는 병렬 Hydrogen 서브에이전트를 지휘하는 Orchestrator 역할도 한다. 원문은 Antigravity에서 SWE-sweep 39.0%, Terminal-Bench 4.1 65.2%를 기록했다고 밝혔다.
어떻게 쓰나 Google Antigravity에서 유료 Pro·Ultra 구독자가 쓴다. 원문 예시에는 /swarm 명령으로 에이전트 군집 작업을 돌리고 Blender MCP를 구동하는 사례가 나온다. 자세한 설정법은 원문에 없다.
의미 대규모 저장소를 다루거나 여러 에이전트를 병렬로 돌리는 개발자에게 해당한다.
출처1
Genie 4와 Project Genie 에이전트·갤러리
무엇 Genie 4는 Project Genie의 새 월드 모델(세계 생성 모델)이다. 탐험 중 텍스트 프롬프트로 날씨를 바꾸거나 캐릭터를 추가하는 등 환경을 실시간으로 수정할 수 있다. 장면에 맞춰 바뀌는 네이티브 오디오도 처음 지원한다. 새 Project Genie 에이전트는 대화로 월드를 만들어 준다. 커뮤니티 갤러리에서는 월드를 탐험하고 리믹스하고 게시할 수 있다. 생성물에는 SynthID 워터마크가 들어간다.
어떻게 쓰나 Project Genie 웹사이트에서 쓴다. 자격이 되는 Google AI Ultra 구독자는 오늘부터 쓸 수 있다. Google AI Pro 회원은 같은 페이지에서 대기자 명단에 등록한다. 원문 관련 기사 목록에는 Gemini API에서 Genie 4를 쓸 수 있다는 항목이 있지만, 이 원문에는 자세한 내용이 없다.
의미 인터랙티브 월드 생성과 프로토타입에 관심 있는 크리에이터에게 의미가 있다. 일반 개발 작업과는 거리가 멀다.
출처1
Genie 3 업데이트
무엇 Genie 3는 Project Genie 모델 선택기에 그대로 남아 있다. 생성 1회당 탐험 시간이 60초에서 최대 3분으로 늘었고, 여러 월드를 연결하는 월드 체이닝을 지원한다. 360도 파노라마 이미지로 새 월드를 만드는 파노라마 그라운딩도 가능하다. 탐험 중 자연어로 환경을 바꾸는 실시간 이벤트도 지원한다.
어떻게 쓰나 Project Genie의 모델 선택기에서 Genie 3를 고른다. Ultra 구독자 대상이다.
의미 더 긴 탐험이나 파노라마 기반 공간이 필요할 때 Genie 3를 고르면 된다.

Gemini 4 Neon for cyber (Fairwind Program)
무엇 Neon의 사이버 보안용 버전이다. 취약점 탐색, 악용 가능성 검증, 패치까지 코드 보안 강화 전 과정을 다룬다. 원문 수치는 SEC-bench Pro 90.5%, WebExploitBench v1.2 51.26%, CWE-bench v2 70.7%다. 대형 모델보다 빠르고 비용 효율이 높다고 밝혔다.
어떻게 쓰나 Fairwind Program을 통해 신뢰받는 방어자(trusted defenders)에게 앞으로 며칠 안에 제공한다. 신청 방법은 원문에 없다.
의미 보안 팀과 방어 목적의 연구자에게 해당한다. 그 밖의 개발자는 일반 Neon에서 보안 코드 생성이 개선됐다는 정도만 알면 된다.

해설 보기 · modelcontextprotocol/servers v2.5.0은 mcp-server-git, server-filesystem, server-everything의 보안 취약점 8건을 고친 보안 릴리스다. 모든 참조 서버가 Streamable HTTP도 지원하게 됐고, memory 서버에는 쓰기 제한 옵션이 들어갔다. 그 밖에 문서·CI·의존성 정리 등 내부 변경이 있다.
mcp-server-git 2026.11.18 보안 수정 6건
무엇 저장소 설정이 서버 권한으로 외부 프로그램을 실행하게 만들 수 있던 문제들을 막았다. git_merge 뒤 자동 maintenance 실행을 끄고(maintenance.auto=false, gc.auto=0), 누락된 객체의 lazy fetch를 끄고(GIT_NO_LAZY_FETCH=1), 파일을 쓴 뒤 filter·merge driver를 다시 읽는다. 빈 이름 driver도 비우고, 작업 트리 밖을 가리키는 index 항목을 거부하며, submodule 설정이 프로그램을 실행하지 못하게 했다.
어떻게 쓰나 mcp-server-git를 2026.11.18로 올린다. 설정할 것은 없다. 낡은 Git에서는 promisor remote가 선언된 저장소나, submodule을 체크아웃한 저장소(Git 2.33 미만)를 거부한다. --repository 제한 검사는 쓰기 뒤에 아직 반복되지 않는다(#5599).
의미 신뢰할 수 없는 저장소를 mcp-server-git로 다루는 사용자는 바로 업그레이드해야 한다. 영향 범위는 2026.11.11까지의 버전이다.

server-filesystem 2.4.0: 디렉터리 목록 검사 우회 수정
무엇 list_directory, list_directory_with_sizes, directory_tree, search_files가 디렉터리를 검사한 뒤 같은 디렉터리를 그대로 나열한다. 검사와 나열 사이에 디렉터리를 symlink로 바꿔치기해도 허용 디렉터리 밖의 항목 이름이 반환되지 않는다. 이 보호는 Linux와 macOS에만 적용되고, Windows는 아직 고정되지 않았다(#5600).
어떻게 쓰나 날짜 버전(2025.x, 2026.x) 사용자는 패키지 관리자가 2.4.0을 업그레이드로 제안하지 않는다. 직접 설치해야 한다: npm install @modelcontextprotocol/server-filesystem@2.4.0
의미 filesystem 서버를 쓰는 사용자에게 의미가 있다. 날짜 버전을 쓰고 있다면 명시적으로 설치해야 한다. Windows에서는 이 수정이 적용되지 않는다.

server-everything 2.3.1: NAT64 주소로 사설 IP 접근 차단
무엇 gzip-file-as-resource 도구의 사설 주소 차단 로직이 64:ff9b::/96 대역(NAT64)을 공개 주소로 잘못 판단했다. NAT64 게이트웨이가 있는 네트워크에서는 이를 통해 사설 IPv4 주소에 닿을 수 있었다. 이제 내장된 IPv4 주소를 검사한다.
어떻게 쓰나 @modelcontextprotocol/server-everything을 2.3.1로 올린다.
의미 NAT64 환경에서 이 테스트용 참조 서버를 쓰는 경우에만 해당한다. 그 외에는 몰라도 된다.

모든 참조 서버의 Streamable HTTP 지원
무엇 각 참조 서버(everything, filesystem, memory, sequential-thinking, fetch, git, time)가 Streamable HTTP로도 서비스할 수 있게 됐다(#5536). 원문은 제목 수준만 언급하며, 세부 동작은 적혀 있지 않다.
어떻게 쓰나 원문에 사용법 없음
의미 HTTP로 연결해 서버를 쓰려는 개발자에게 의미가 있다. stdio만 쓴다면 몰라도 된다.
출처1
memory 서버 쓰기 제한 옵션과 lock 처리 개선
무엇 server-memory 2.2.1에 그래프 크기에 대한 opt-in 쓰기 제한이 추가됐다(#5534). 종료나 SIGINT/SIGTERM 때 잡고 있던 lock 파일을 풀고, stale lock을 깰 때 다른 프로세스의 살아 있는 lock을 지우지 않게 했다. Streamable HTTP 서버가 멈출 때도 lock을 푼다.
어떻게 쓰나 원문에 사용법 없음. 쓰기 제한은 선택 사항(opt-in)이라는 설명만 있고, 설정 이름은 적혀 있지 않다.
의미 memory 서버를 장기간 돌리거나 여러 프로세스에서 쓰는 사용자에게 도움이 된다.
